# Code Review

## 1. `common/json-schema-to-grammar.cpp`

### Bug: `_add_rule` collision loop can infinite-loop or produce wrong names

```cpp
std::string _add_rule(const std::string & name, const std::string & rule) {
    // ...
    int i = 0;
    while (_rules.find(esc_name + std::to_string(i)) != _rules.end() && 
           _rules[esc_name + std::to_string(i)] != rule) {
        i++;
    }
```
If a key exists with *different* content, this increments until it finds either an empty slot or matching content — but if many keys exist with different rules, this could scan far. More importantly, when it exits because `_rules[key] == rule`, it still assigns to that key (correct), but if it exits because the key doesn't exist yet, it also assigns correctly. The logic is correct but fragile; consider using a counter map instead.

### Issue: `build_min_max_int` uses `int64_t` sentinel values as "unset"

```cpp
auto has_min = min_value != std::numeric_limits<int64_t>::min();
auto has_max = max_value != std::numeric_limits<int64_t>::max();
```
This means you cannot express a schema whose minimum is literally `INT64_MIN`. This is a design limitation worth documenting explicitly in the header.

### Minor: `GRAMMAR_RANGE_LITERAL_ESCAPE_RE` is defined but never used

```cpp
static std::regex GRAMMAR_RANGE_LITERAL_ESCAPE_RE("[\r\n\"\\]\\-\\\\]");
```

## 2. `common/arg.cpp`

### Bug: `parse_csv_row` always pushes at least one field even for empty input

```cpp
// Add the last field
fields.push_back(std::move(field));
return fields;
```
For an empty string `""`, this returns `{""}` — a single empty element. Callers like `--host` filter empties afterward so it's safe there, but other callers (e.g., `--api-key`) may not expect this.

### Concern: Static mutable state in argument handlers

```cpp
static bool defaults_cleared = false; // inside --dry-sequence-breaker handler
```
and:
```cpp
static std::list<std::string> buft_overrides; // inside parse_tensor_buffer_overrides
```
These are function-local statics that persist across calls and are **not thread-safe** if parsing ever happens concurrently. The `buft_overrides` list grows unboundedly by design (to keep strings alive), which is intentional but should be documented more clearly.

## 3. `common/chat-auto-parser-generator.cpp`

### Design concern: Grammar construction depends on tool format detection heuristics

The three parser builders (`build_tool_parser_json_native`, `build_tool_parser_tag_json`, `build_tool_parser_tag_tagged`) each have subtly different whitespace handling around section markers, per-call wrappers, and closing tags.
