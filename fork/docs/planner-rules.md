# Planner rules: contradictions, resolutions, invariants (2026-11-07, tree at 1de0303b9e)

Scope: the prompt-pass planner (MC = src/llama-moecache-fork.cpp), the dense-split planner (DS = src/llama-dsplit-fork.cpp), the pass-size and
thread tuners (CTX = src/llama-context.cpp), the RAM pool's placement (RP = ggml/src/ggml-rampool-fork.cpp, MC rp_heat). Line numbers are of the
working tree at 1de0303b9e (the learned planner, `--moe split-model=1` default, with the old cascade kept under `split-model=0`). Evidence is from
fork/runs.db (`runs` rowids, `prompt_passes` rowids as "pp#") and the logs cited in fork/docs/rampool.md. Read rampool.md "Robust planner design"
and "Planner rules inventory" first; this file lists what in there and in the new code still contradicts itself, and what Opus applies in order.

Severity: the loss of the chosen path against the measured faster one, as a share of the call ("call") and of the whole request where the request
is known ("req"). Every number is a measured row; none is a model's.

## 2. Resolutions, in the order Opus applies them

Each item names the code it touches and what replaces it. "delete" = the rule and its state go (under `split-model=0` only where the inventory says
"old"); "predictor" = it becomes a feature or a sample of the one RLS per path; "feasibility" = it stays as a hard constraint with no number in it.

1. **C4 + C13, the prior and the fill, before anything else** (the first start of every build runs on it). DS:2627: `c_prior = plan.t_raw_ms * c_split / n`
   (no fill, no refill), or simply `plan.t_raw_ms / n`. DS:1088-1092: delete the refill term and `refill_weight` from the plan (unmeasured: C13's rows show no
   decode dip); the plan's `t_split_ms` keeps the fill ONLY for the `split-model=0` cascade; under `split-model=1` the plan is read for the shares alone
   (DS:2889), so its fill is harmless there once the prior comes from `t_raw_ms`. Self-check: at `rls_init` of `g_rls_split`, log `prior per token` next to
   `plan.t_raw_ms / n` and assert they are equal.
2. **C17, regret over every path** (so the acceptance cells can see C2/C3/C8/C9). MC:11972: `lo` = min over the one-card candidates AND the split's
   predicted mean for the same pass (export `llama_dsplit_split_pred_us_fork(n, c)` = `rls_pred(g_rls_split, phi)`; -1 when not managed). DS:2708: before
   the return, when `p.choice == 0 && p.mu >= 0`, book `max(0, us - p.lo)` with `p.lo` as set at DS:2676 (both means). One `plan_regret_s`, booked once per
   pass by whichever side timed it: a split pass by DS:2748, a one-card pass by MC:11975; never both (assert `g_pp_pick != -1` xor `p.choice == 1` per pass).
3. **C18, a one-card estimator for every managed model.** DS: `static dsf_rls g_rls_one` (k = 4, prior from `plan.t_one_ms / n` with P = diag(th0^2)).
   `dsf_plan`: when `llama_moe_cache_pp_one_draw_fork` returns -1, `one_k = rls_draw(g_rls_one, phi)`; `dsplit_pass_end_locked`: a `choice == 0` pass with no
   moe-cache candidate (`g_pp_phi` empty: new export `llama_moe_cache_pp_planned_fork()`) updates `g_rls_one` with `phi = (1, T, T cm, 0)`. Then DS:2902's
   fallback to the cascade is only `split-model=0`; delete "or no one-card candidate planned for this call". `--moe cache` off, chain off and a fixed ubatch
   are then the same planner with fewer candidates.
4. **C19 + C20 + C21, one pass size, decided before the path and known to it.** CTX: move `llama_moe_cache_pp_decide_fork` (4370) after `n_ubatch_call` (4376-4377)
   and pass `n_ubatch_call` as `ub_max`; MC:11609 `pp_add` keeps the planned U per pass. MC:11802: `mirror_b` is charged only when the request's copies are
   not in place AND the split is possible (`llama_dsplit_managed_fork()`); the split's choice still comes after, so a one-card call that follows a split
   call keeps the room (the copies are in the pool) and a cold one-card call does not pay for copies it never fills. CTX:4431: the 3/4 shrink stays
   (feasibility: the KV did not fit) but calls `llama_moe_cache_pp_repass_fork(n_ubatch_call)` so `g_pp_phi` and `g_pp_U_us` are re-featured for the pass
   that runs; `g_pass_cap_fork` is cleared at the end of the call (it is, CTX; verify) and logged as a `prompt pass` decision line (it is).
5. **C16, the predictions' feature.** MC:12231: `cand(PP_K + i, U_staged_i)` where `U_staged_i` = the stream's upload less what q2 staging of `2^i x picks`
   would hide: `Ts * max(0, 1 - 2^i * n_used / n_expert)` is the shape the existing `pp_k_pick` reasoned with ("ranks do not reach all experts"); the
   coefficient learns the rest. Then the arms differ in mean from the start and the draw is not a coin flip. Keep the stream-posterior copy (MC:11486) as the prior.
6. **C1 + R3, the decode chain's upload feature.** MC:12230: `cand(PP_DEC, up + chunk_at(n) + ssd_term)` where `ssd_term` = the bytes of the misses still

   stay for the CAL log line and `split-model=0` only (they are, verify no learned-path read of `de`/`ot`: MC:12254 `dec_ok` is under the old branch, ok).
7. **C6, every pass is a sample.** MC:12000-12009: the cold/cold_dec skips apply to `g_pp_took` (old) only; the RLS update at 11967 already runs before

8. **C2 + C3 + C5 + C8 + C9 + C10 + C11 + C12 + C14 + C15 (the cascade)**: all under `split-model=0` already; verify nothing of them is read on the default

   (DS:2510 inside `dsf_decide`, not called in learned mode, ok; DS:2759 after the learned return, ok), `g_dsf_urat` (DS:2722 `!learned`, ok), the
   quarter rule (DS:2714 `!learned`, ok), `split_min_gain` (DS:2930/2940/2980 else branch; DS:2605 `dsf_decide`, ok), `pp_try_ok` (MC old branch, ok).
   Delete them in the release after, with `split-model`. Until then the invariant check I5 below guards the default path.
9. **C7, chain and prediction passes.** They are their own paths with their own RLS (they are: PP_CHAIN, PP_K+i), so DS:2705's "says nothing about one card"

10. **C22, the thread tuners.** Not in the planner; leave, but make the tie-break the same (fewer threads win a tie in both: the batch tuner's rule, the user's
    "too few costs a lot" argument is about the search direction, not the tie) and log it once. Lowest priority.
11. **R1 + R2, the RAM tier.** `rp_heat`: a card-held expert's heat = its decode heat (vis_next) with no HUGE_VAL when the model has prompt passes that lend

    lands in RAM). `queued` never counts as held. The fill then holds the hottest N whatever the cards hold. Log per decode call the misses served from

## 3. Invariants the planner must satisfy, with a runtime self-check each

Every check logs ONCE per violation class to stats.log as `INV <name>: ...` (and `/moe/stats` `inv_<name>` counter); never an abort in a release build
(`GGML_ASSERT` under `--moe inv-abort=1` for test cells).

- **I1. No measured path is overruled by a model.** For a pass of size n at c cells: if path A was measured at a phi within 10% of this pass's phi (n and c)
  and B was not, and the pick is B, then B's drawn time must be below A's POSTERIOR MEAN minus one sigma with probability from the draw alone: log
  `INV overrule` when the picked path's posterior mean is above another candidate's mean + sigma of both and the picked path has n > 0 samples (then it
  was not exploration of an unknown, it was a worse known). Check at MC:12238 and DS:2670 (both picks).
- **I2. A one-time cost is never charged to a per-request decision, and a per-request cost never to a per-pass one.** Pins: assert `pin_ms` never enters
  `g_rls_fill` (DS:2787 uses `copy_ms`: keep) and never a pass sample (DS:2718 `fill_wall_ms`: keep). Fill: charged at most once per request: counter
  `fill_charged_req` reset on a new request (`g_dsf_seen_pos0` rule), log `INV fill twice` when `dsf_plan` adds `f_d > 0` while `g_dsf_call_fill_ms > 0`
  for this call or the copies are in place (`g_mirror_fill_us == 0`).
- **I3. Each cost is measured once and counted once.** The split pass sample = pass wall - fill wall - up-wait (DS:2718, 2733), the fill sample = wall -
